## 1. 문서 개요

**목적**: `2-PRD.md`(v0.2.0)에서 정한 MVP 범위(UC-01/02/04/05/06/07/08/09, P0/P1)를 실제 화면 레이아웃으로 구체화하여, 프론트엔드 구현 시 참고할 화면 구조와 컴포넌트 배치 기준을 제공한다.

**관련 문서와의 관계**: 용어·엔티티·비즈니스 규칙(BR-ID)·유스케이스(UC-ID)·상태 판별 규칙은 `1-domain-definition.md`(v0.4.0)를 단일 출처로 참조한다. 우선순위·범위·기술 스택은 `2-PRD.md`(v0.2.0)를 참조한다. 화면 흐름의 근거가 되는 사용자 행동 시나리오는 `3-user-scenario.md`(v0.1.1)를 참조한다. 본 문서는 세 문서를 재정의하지 않고 UC-ID/BR-ID를 인용만 하며, 시각적 레이아웃과 컴포넌트 배치에 집중한다.

**표기 방식**: 이미지 파일 대신 마크다운 코드블록 안 ASCII(box-drawing) 아트로 레이아웃을 표현한다. 주요 화면마다 데스크톱(≥1024px)과 모바일(반응형, ~375px 기준) 레이아웃을 함께 제시한다.

## 2. 화면 목록 및 흐름 개요

| # | 화면              | 관련 UC-ID    | 우선순위 |
| - | ----------------- | -------------- | -------- |
| 1 | 회원가입           | UC-01          | P0       |
| 2 | 로그인             | UC-02          | P0       |
| 3 | 할일 목록          | UC-05, UC-06   | P0/P1    |
| 4 | 할일 등록          | UC-04, UC-09   | P0       |
| 5 | 할일 편집          | UC-07          | P0       |
| 6 | 삭제 확인          | UC-08          | P0       |
| 7 | 회원정보 수정      | UC-03          | P2       |
| 8 | 캘린더 보기(목록 화면 내 전환) | UC-10 | P2       |

**화면 흐름도**:

```
[회원가입] --가입 성공--> [로그인]
[로그인] --인증 성공--> [할일 목록] <--------------------+
                            |  |  |                       |
                 "할일 추가"|  |  |"편집"                  |
                            v  |  v                       |
                    [할일 등록]|  [할일 편집] --저장--------+
                       |       |     |
                       +--저장-+     +--"삭제"--> [삭제 확인] --확인--> [할일 목록]
                            |
                     (필터 UI는 목록 화면 내부, 별도 화면 전환 없음)

[할일 목록] --헤더 "내 정보"--> [회원정보 수정] --저장/취소--> [할일 목록]
[할일 목록] --헤더 "로그아웃"--> [로그인]
```

- 로그인 전 접근 가능 화면: 회원가입, 로그인뿐이다. 그 외 전 화면은 인증 필요(BR-01, 전역 전제).
- 할일 등록/편집은 목록 화면 위 모달 또는 별도 라우트로 열 수 있으나, 본 문서는 레이아웃 기준으로 별도 화면(풀페이지 기준)으로 표현한다. 실제 구현 시 모달/페이지 여부는 개발 단계에서 선택 가능.

## 5. 할일 목록 화면 (UC-05, UC-06)

**데스크톱**

```
┌──────────────────────────────────────────────────────────────────┐
│ TodoList     [+ 할일 추가]                    내 정보  로그아웃    │  ← 공통 헤더
├──────────────────────────────────────────────────────────────────┤
│ 카테고리: [전체 ▾]   상태: [전체][시작전][진행중][완료][지연]  [목록][캘린더]│  ← 필터 바(UC-06) + 보기 전환(UC-10)
├──────────────────────────────────────────────────────────────────┤
│ ┌──────────────────────────────────────────────────────────────┐ │
│ │ [ ] 알고리즘 과제            [기본]      2026-08-26~09-02 [진행중]│ │
│ ├──────────────────────────────────────────────────────────────┤ │
│ │ [ ] DB 프로젝트 발표자료      [학업]     2026-08-20~08-25  [지연]│ │
│ ├──────────────────────────────────────────────────────────────┤ │
│ │ [✔] 거래처 미팅 자료 정리     [업무]     2026-08-10~08-20  [완료]│ │
│ ├──────────────────────────────────────────────────────────────┤ │
│ │ [ ] 분기 보고서 작성          [업무]     2026-09-01~09-10 [시작전]│ │
│ └──────────────────────────────────────────────────────────────┘ │
│                                                                      │
│ (할일 없을 때) "등록된 할일이 없습니다. 새 할일을 추가해 보세요."     │
└──────────────────────────────────────────────────────────────────┘
```

- 각 행: 완료 체크박스 / 제목 / 카테고리 뱃지 / 기간(시작일~종료일) / 상태 뱃지. 행 클릭 시 편집 화면(UC-07)으로 이동.
- 완료 체크박스를 목록에서 직접 토글하면 UC-07의 완료 처리(BR-07)를 간이 실행(선택적 구현, 상세 편집은 편집 화면에서).

**모바일 (반응형)**

```
┌───────────────────┐
│ TodoList      ☰    │  ← 헤더, ☰ 탭하면 내 정보/로그아웃 메뉴
├───────────────────┤
│ [+ 할일 추가]       │
├───────────────────┤
│ 카테고리 [전체 ▾]   │
│ 상태 [전체 ▾]       │  ← 필터는 드롭다운으로 축소
├───────────────────┤
│ ┌─────────────────┐│
│ │[ ] 알고리즘 과제  ││
│ │ 기본 · 진행중     ││
│ │ 08-26~09-02      ││
│ ├─────────────────┤│
│ │[ ] DB 프로젝트    ││
│ │ 학업 · 지연       ││
│ │ 08-20~08-25      ││
│ ├─────────────────┤│
│ │[✔] 거래처 미팅    ││
│ │ 업무 · 완료       ││
│ │ 08-10~08-20      ││
│ └─────────────────┘│
└───────────────────┘
```

**비고**
- 데스크톱은 상태 필터를 탭/버튼 그룹으로, 모바일은 공간 제약상 드롭다운(select)으로 축소해 표시한다.
- 목록은 본인 소유 할일만 반환(BR-02), 상태는 조회 시점 계산값(BR-06, 도메인정의서 5장 판별 규칙)이므로 서버 응답 기준 그대로 뱃지 표시.

## 5.1 캘린더 보기 (UC-10)

목록 화면의 "캘린더" 버튼을 누르면 같은 필터 조건의 할일을 아래처럼 월간 그리드로 전환해 보여준다. "목록" 버튼으로 되돌아갈 수 있다.

```
┌──────────────────────────────────────────────────────────────────┐
│ TodoList     [+ 할일 추가]                    내 정보  로그아웃    │
├──────────────────────────────────────────────────────────────────┤
│ 카테고리: [전체 ▾]   상태: [전체][시작전][진행중][완료][지연]  [목록][캘린더]│
├──────────────────────────────────────────────────────────────────┤
│              ‹        2026년 9월        ›                          │
│  일    월    화    수    목    금    토                              │
│ ──── ──── ──── ──── ──── ──── ────                              │
│                    1     2     3     4     5                       │
│                  [알고리즘 과제]                                    │
│  6     7     8     9    10    11    12                             │
│       [DB 프로젝트 발표자료]                                        │
│ 13    14    15    16    17    18    19                             │
└──────────────────────────────────────────────────────────────────┘
```

- 그리드는 일요일 시작 6주(42칸), 이전/다음 달 날짜도 채워 넣되 옅게 표시.
- 할일은 시작일~종료일에 걸친 모든 날짜 셀에 상태 색상(10.2절)으로 표시. 한 셀에 여러 건이면 최대 3건만 보여주고 나머지는 "+N개"로 축약.
- 항목 클릭 시 편집 화면(UC-07)으로 이동. 신규 API 없이 목록 조회(UC-05/06) 결과를 그대로 재사용.
- 모바일은 셀 높이만 축소, 레이아웃 구조는 동일하게 유지(별도 모바일 전용 레이아웃 없음, YAGNI).

│ 할일을 삭제하시겠습니까?          │
│                                 │
│ "DB 프로젝트 발표자료"           │

│                                 │

**비고**
- 모달(오버레이) 형태로 목록/편집 화면 위에 표시. 화면 크기와 무관하게 동일 레이아웃 사용(반응형 시 폭만 화면 대비 비율 조정, 예: 데스크톱 400px 고정 / 모바일 화면 폭의 90%).
- [삭제하기] 확정 시 서버 요청 후 할일 목록으로 복귀, 목록에서 즉시 제거 확인(도메인정의서 7.1 UC-08 수용기준). 타인 소유 할일이면 서버에서 거부(BR-02).

## 10. 공통 컴포넌트 메모

### 10.1 헤더/네비게이션
- 좌측: 서비스 로고(클릭 시 할일 목록 `/todos`로 이동), 우측: 언어 선택(ko/en/ja/zh) / 다크모드 토글(🌙·☀️) / "내 정보"(UC-03) / "로그아웃".
- 로그인 안 한 상태에서는 언어 선택·다크모드 토글만 노출, "내 정보"/"로그아웃"은 숨김.
- 모바일에서는 별도 햄버거 메뉴 없이 `flex-wrap`으로 다음 줄에 줄바꿈해서 표시(항목이 4개뿐이라 YAGNI — 컴포넌트 늘리지 않음).
- 로그인 화면·회원가입 화면에는 이 헤더 대신 로고만 표시(비인증 상태, 언어·테마 설정은 유지되지만 전환 UI는 없음).
- 지면상 3·5·6·7·9장의 ASCII 목업은 언어 선택/다크모드 토글을 생략하고 "내 정보 로그아웃"만 그렸다. 실제 헤더는 이 절 기준이 맞다.

### 10.2 상태 뱃지 색상 규칙
상태 판별 로직 자체는 재정의하지 않으며 도메인정의서 5장(상태 판별 규칙, 우선순위: 완료 > 지연 > 진행중 > 시작 전)을 그대로 따른다. 색상은 화면상 구분을 위한 시각 규칙만 정의한다.

| 상태     | 색상 예시        | 비고                              |
| -------- | ----------------- | --------------------------------- |
| 시작 전  | 회색 (Gray)        | 아직 도래하지 않은 일정            |
| 진행중   | 파랑 (Blue)        | 오늘이 기간 내                     |
| 완료     | 초록 (Green)       | isDone=true, 기간과 무관하게 완료  |
| 지연     | 빨강/주황 (Red)     | 미완료 + 종료일 경과, 주의 환기 필요 |

- 뱃지는 텍스트 라벨 + 색상을 함께 사용(색상만으로 구분하지 않음). 접근성은 이번 범위 제외(PRD 6장)이나, 색상 단독 구분을 피하는 것은 향후 접근성 대응 시 추가 비용을 줄이기 위한 최소한의 배려로 유지한다.

### 10.3 카테고리 뱃지
- 회색조 텍스트 뱃지(예: `[기본]`, `[업무]`, `[학업]`)로 상태 뱃지와 시각적으로 구분.
- 카테고리 미지정 등록 시 항상 `[기본]`으로 표시(BR-04).

### 10.4 폼 공통 규칙
- 필수 필드는 레이블에 `*` 또는 별도 표기, 클라이언트 측 1차 검증 + 서버 측 2차 검증(BR-05 등) 병행.
- 등록/편집/회원가입/로그인 폼은 동일한 카드형 레이아웃(제목 + 필드 스택 + 하단 버튼 그룹)을 재사용해 일관성을 유지한다.

### 10.5 반응형 브레이크포인트 (제안)
- 데스크톱: ≥1024px — 콘텐츠 중앙 정렬, 최대 폭 제한(예: 960px), 필터/버튼 가로 배치.
- 모바일: <768px — 전체 폭 사용, 필터 드롭다운화, 버튼 세로 스택.
- 구체적 브레이크포인트 값은 구현 단계에서 조정 가능하며, 본 문서는 레이아웃 전환 원칙만 제시한다.
