## 1. 문서 개요

**목적**: TodoList 웹 애플리케이션 개발에 앞서 도메인 용어, 핵심 엔티티, 비즈니스 규칙을 정의하여 이후 요구사항 정의서·DB 설계·API 설계의 기준을 제공한다.

**배경 / 문제 정의**:

- 인증된 사용자별로 할일을 개인화하여 관리할 수 있는 앱이 부재하다.
- 할일에 시작일/종료일 개념이 없어 일정 기반 관리(진행 상태, 지연 여부 파악)가 불가능하다.

**전역 전제**: 이 문서의 모든 기능은 로그인(인증)된 사용자를 대상으로 한다 (BR-01). 이하 유스케이스·규칙에서는 이 전제를 별도로 반복 표기하지 않는다.

## 2. 도메인 용어 정의 (Ubiquitous Language)

| 용어                  | 정의                                                                             |
| --------------------- | -------------------------------------------------------------------------------- |
| 사용자 (User)         | 회원가입을 통해 인증 정보를 가진, 앱을 사용하는 주체                             |
| 할일 (Todo)           | 사용자가 등록한 작업 단위. 제목, 기간(시작일/종료일), 완료 여부, 카테고리를 가짐 |
| 카테고리 (Category)   | 할일을 분류하는 사용자 정의 그룹. 미지정 시 '기본' 카테고리로 자동 분류. **MVP 범위에서는 사용자가 직접 카테고리를 생성하는 API/화면은 제공하지 않으며, 가입 시 자동 생성되는 '기본' 카테고리만 존재한다**(7장 UC-09, BR-04 참조) |
| 상태 (Status)         | 할일의 진행 국면. 시작 전 / 진행중 / 완료 / 지연 4가지로 구분                    |
| 시작일자 (Start Date) | 할일 수행이 시작되는 날짜                                                        |
| 종료일자 (End Date)   | 할일 수행이 종료되어야 하는 날짜(마감일)                                         |
| 완료 여부 (Is Done)   | 사용자가 할일을 완료 처리했는지 나타내는 플래그                                  |
| 지연 (Overdue)        | 종료일자가 지났음에도 완료되지 않은 할일의 상태                                  |

## 3. 핵심 도메인 엔티티 및 속성

### 3.1 User (사용자)

| 속성      | 타입         | 필수 | 설명                        |
| --------- | ------------ | ---- | --------------------------- |
| id        | 식별자       | 필수 | 사용자 고유 식별자 (PK)     |
| email     | 문자열       | 필수 | 로그인 계정, 고유값(unique) |
| password  | 문자열(해시) | 필수 | 인증용 비밀번호             |
| name      | 문자열       | 필수 | 사용자 표시 이름            |
| createdAt | 일시         | 필수 | 가입일시                    |
| updatedAt | 일시         | 필수 | 회원정보 최종 수정일시      |

### 3.2 Category (카테고리)

| 속성      | 타입   | 필수 | 설명                                     |
| --------- | ------ | ---- | ---------------------------------------- |
| id        | 식별자 | 필수 | 카테고리 고유 식별자 (PK)                |
| userId    | 식별자 | 필수 | 소유 사용자 (FK)                         |
| name      | 문자열 | 필수 | 카테고리명. 사용자별 고유. 기본값 '기본' |
| createdAt | 일시   | 필수 | 생성일시                                 |

### 3.3 Todo (할일)

| 속성        | 타입   | 필수 | 설명                                                 |
| ----------- | ------ | ---- | ---------------------------------------------------- |
| id          | 식별자 | 필수 | 할일 고유 식별자 (PK)                                |
| userId      | 식별자 | 필수 | 소유 사용자 (FK)                                     |
| categoryId  | 식별자 | 필수 | 소속 카테고리 (FK, 미지정 시 '기본' 카테고리로 대체) |
| title       | 문자열 | 필수 | 할일 제목                                            |
| description | 문자열 | 선택 | 상세 설명                                            |
| startDate   | 날짜   | 필수 | 시작일자                                             |
| endDate     | 날짜   | 필수 | 종료일자 (startDate 이상이어야 함)                   |
| isDone      | 불리언 | 필수 | 완료 여부. 기본값 false                              |
| completedAt | 일시   | 선택 | 완료 처리 일시 (isDone=true 시 설정)                 |
| createdAt   | 일시   | 필수 | 등록일시                                             |
| updatedAt   | 일시   | 필수 | 최종 수정일시                                        |

> 상태(시작 전/진행중/완료/지연)는 별도 저장 컬럼이 아니라 startDate, endDate, isDone 값으로부터 파생되는 계산값이다 (5장 참조).

## 4. 엔티티 관계

- User 1 : N Category (한 사용자는 여러 카테고리를 가질 수 있다)
- User 1 : N Todo (한 사용자는 여러 할일을 가질 수 있다)
- Category 1 : N Todo (한 카테고리는 여러 할일을 가질 수 있다)
- Todo는 반드시 하나의 User와 하나의 Category에 속한다 (categoryId 필수, 기본값 '기본')

## 5. 할일 상태(Status) 정의 및 판별 규칙

기준일: 오늘 날짜(today), 판단 시점의 시스템 날짜 기준

| 상태                  | 판별 규칙 (우선순위 순)                          |
| --------------------- | ------------------------------------------------ |
| 완료 (Done)           | isDone = true                                    |
| 지연 (Overdue)        | isDone = false AND endDate < today               |
| 진행중 (In Progress)  | isDone = false AND startDate <= today <= endDate |
| 시작 전 (Not Started) | isDone = false AND startDate > today             |

규칙 적용 순서: 완료 여부를 최우선으로 판별하고, 미완료 건에 한해 날짜 조건으로 시작 전/진행중/지연을 구분한다. 즉 완료된 할일은 종료일이 지났어도 '지연'이 아닌 '완료'로 표시한다.

## 6. 비즈니스 규칙 및 제약사항

| ID    | 규칙                                                                                                                   |
| ----- | ------------------------------------------------------------------------------------------------------------------- |
| BR-01 | 인증되지 않은 사용자는 할일/카테고리에 접근할 수 없다 (로그인 필수).                                                  |
| BR-02 | 사용자는 자신이 소유한 할일/카테고리/회원정보만 조회·수정·삭제할 수 있다 (소유권 검증 필수).                          |
| BR-03 | 회원가입 시 email은 유일해야 하며, 동일 email로 중복 가입할 수 없다.                                                  |
| BR-04 | 할일 등록 시 카테고리를 지정하지 않으면 해당 사용자의 '기본' 카테고리로 자동 지정한다. '기본' 카테고리는 사용자별로 최초 1회 자동 생성되며 삭제할 수 없다. |
| BR-05 | 할일의 endDate는 startDate보다 빠를 수 없다 (startDate <= endDate).                                                   |
| BR-06 | 할일 상태는 저장값이 아닌 조회 시점의 계산값이다 (5장 규칙 적용).                                                     |
| BR-07 | 할일을 완료 처리하면 completedAt에 처리 일시를 기록한다. 완료 취소 시 completedAt은 초기화한다.                       |

### 7.1 수용 기준 (Acceptance Criteria)

| ID    | Given                          | When                              | Then                                                     |
| ----- | ------------------------------- | ---------------------------------- | --------------------------------------------------------- |
| UC-01 | 미가입 email                    | email/password/name으로 가입 요청  | 계정 생성됨, 중복 email이면 가입 거부 (BR-03)              |
| UC-02 | 가입된 계정                     | 올바른 email/password로 로그인 요청 | 인증 토큰 발급, 틀린 경우 인증 실패                        |
| UC-03 | 로그인된 사용자                 | 본인 name/password 수정 요청       | 정보 반영, 타인 정보 수정 시도는 거부 (BR-02)              |
| UC-04 | 로그인된 사용자                 | 제목/시작일/종료일(/카테고리) 입력 후 등록 | 할일 생성, endDate < startDate면 거부 (BR-05), 카테고리 미지정 시 '기본' 적용 (BR-04) |
| UC-05 | 본인 소유 할일 N건 존재          | 목록 조회 요청                     | 본인 할일만 반환, 각 항목에 계산된 상태 포함 (BR-06)        |
| UC-06 | 상태/카테고리 혼재된 할일 목록   | 필터 조건 지정 후 조회             | 조건에 부합하는 할일만 반환                                |
| UC-07 | 본인 소유 할일                  | 편집 화면에서 필드 수정 후 저장    | 변경 반영, endDate<startDate 거부 (BR-05), isDone→true 시 completedAt 기록 (BR-07), 타인 소유 시 거부 (BR-02) |
| UC-08 | 본인 소유 할일                  | 삭제 요청                          | 할일 제거, 타인 소유 할일 삭제 시도는 거부 (BR-02)          |
| UC-09 | 로그인된 사용자, 카테고리 미지정 | 할일 등록                          | '기본' 카테고리로 자동 연결 (BR-04)                        |

## 8. Out of Scope (이번 범위 제외)

- 할일/카테고리의 타 사용자와의 공유 및 협업 기능
- 이메일·푸시 등 알림 기능
- 첨부파일 업로드
- 할일 우선순위, 태그, 반복(recurring) 일정
- 소셜 로그인 등 외부 인증 연동
- 다국어(i18n) 지원
